# Unity C#

- **No gameplay logic in Unity.** Unity reads the simulation through `GodGame.Bridge` and writes only the plan. If a feature seems to need gameplay in Unity, the simulation is missing something: add it there.
- **No static mutable state.** Enter Play Mode runs without domain reload, and Unity is moving to CoreCLR; statics are not reset between plays. Create state in `OnEnable`/`Awake` and drop it in `OnDisable`.
- **Nothing per soldier on the CPU main thread.** No `Update()` per soldier, no GameObject per soldier: indirect instanced draws, compute culling and jobs for anything per unit.
- **The main thread never waits on the simulation** (from M4): read the newest playback samples from the SimHost buffer.
- **Assemblies:** Bridge (SimHost, playback, field upload, plan editing), Rendering, UI (UI Toolkit), Audio, Editor (editor only), Tests.EditMode / Tests.PlayMode. Keep references one-way: everything may reference Bridge and GodGame.Sim; Bridge references no other game assembly.
- **Units:** the simulation speaks millimetres, centi-degrees and ticks (20 per second); convert at the boundary and nowhere else.
- **Unity YAML** (scenes, prefabs, ProjectSettings) is changed through the editor, editor scripts or the Unity MCP tools, never by hand. `.meta` files are generated by Unity and committed with their assets.
- **Input System** for input, **UI Toolkit** for UI, **Cinemachine 3** for cameras.
- Tests: Edit Mode for bridge logic and tools, Play Mode for replays and rendering smoke tests; run them with the unity-tests skill.
